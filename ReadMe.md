       # Сыщик норм — Video Retrieval (XCLIP)

Проект: нарезка видео на фрагменты + фильтрация “интересных” фрагментов (движение + человек) + ранжирование/поиск по текстовому запросу (text→video retrieval).

---

## Основная идея

### Batch (основной режим)
1) Берёшь папку с исходными видео.
2) Нарезаешь каждое видео на фрагменты фиксированной длины (`segment_seconds`).
3) Фильтруешь фрагменты:
   - `motion_detect`: есть движение (серия >= `min_motion_seconds`)
   - `person_detect`: есть человек в кадре (YOLO, COCO class=0)
4) Оставшиеся фрагменты индексируются (эмбеддинги).
5) По текстовому запросу все фрагменты сортируются по similarity.

Лог вида:
`kept 4/6` означает: из 6 нарезанных сегментов осталось 4 после всех включённых фильтров.

---

## ROI (область интереса)

ROI нужен, чтобы анализировать движение/человека **только внутри заданной области** кадра.

### Формат ROI
`(x, y, w, h)` в пикселях от левого верхнего угла.

### Где применяется ROI
✅ ROI применяется **только** в фильтрах:
- `motion_detect`
- `person_detect`

❌ ROI **не влияет** на нарезку сегментов.

### Важно
- ROI задаётся **один раз** на исходном видео и используется одинаково для всех сегментов этого видео.
- Нарезка (`split_video_mvp`) всегда режет **полный кадр**.
- Если ROI включён (`use_roi=True`) и ROI не задан (`roi=None`) — должно быть интерактивное задание ROI (окно OpenCV) на первом кадре исходника.  
  *(Если в твоей текущей версии проекта ROI всё ещё спрашивается во время нарезки — это баг, который надо убрать.)*

## Конфигурация (ключевое)

Основное — в `config.py`:

- `preprocess.enabled` — включить нарезку+фильтры перед retrieval
- `preprocess.input_root_dir` — папка с исходными видео для batch
- `preprocess.splits_root_dir` — куда писать нарезанные сегменты
- `preprocess.segment_seconds` — длина сегмента
- `preprocess.motion.enabled` — фильтр движения
- `preprocess.person.enabled` — фильтр человека (YOLO)
- `preprocess.use_roi` — включить ROI
- `preprocess.roi` — `(x, y, w, h)` или `None` (если выбирается интерактивно)
